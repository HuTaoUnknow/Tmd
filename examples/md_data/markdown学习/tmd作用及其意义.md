# tmd作用及其意义

tmd 用 Markdown 文档保存知识，用知识树表达文档之间的关系。它适合把“写过一些笔记”逐渐整理成“知道从哪里开始、接下来学什么、哪里可以深入”的个人知识体系。

前节点是 [md语法基础](md语法基础.md)，后节点是 [个人知识树示例](个人知识树示例.md)。先能写清楚一篇笔记，再尝试把多篇笔记连接起来。

## 1. 单篇文档承载一个明确的问题

- 一篇文档围绕一个主题，例如“Java 集合基础”或“如何调用一个接口”。
- 在正文中记录概念、理解过程、操作步骤、例子和复盘。
- 以后遇到相同问题，可以回到这一篇更新内容，减少重复记录。
- 文件仍然是 `.md` 文本；知识关系另外保存，不必把阅读顺序写进文件夹名称。

笔记的价值来自自己的理解和验证。把网上的一段文字复制进来以后，还需要说明它解决了什么问题、在什么条件下适用。

## 2. 文件目录回答“放在哪里”

目录可以按领域整理，例如 `markdown学习`、`网络安全`、`网络运维`。它帮助定位文件，也方便备份。

同一篇文档可能参与多条学习路线。例如“HTTP 基础”既可以作为后端接口的准备，也可以作为前端请求的准备。此时不用复制成两篇，给同一节点连接不同关系即可。

## 3. 知识树回答“怎样学、怎样理解”

| 关系 | 用途 | 本组示例中的表现 |
| --- | --- | --- |
| 前节点 | 进入当前主题前应了解的内容 | 了解 tmd 前先学 Markdown 基础 |
| 后节点 | 学完当前主题后继续的方向 | 了解 tmd 后查看个人学习过程 |
| 上节点 | 同级、可替换的知识或做法 | 例如完成同一界面目标的不同技术方案 |
| 下节点 | 当前主题的详解、练习和实践 | Markdown 基础下面的详解与效果对照 |

前后关系互相联动：如果 B 是 A 的后节点，那么 A 就是 B 的前节点。上节点用于表达同级替代，拥有共同的前后路线；下节点用于补充细节，靠近所属节点展示。

本组示例连接为：

```text
md语法基础 → tmd作用及其意义 → 个人知识树示例
    ├─ md语法详解
    └─ md语法详解示例对照
```

箭头表示主要学习顺序，下面两篇是基础主题的补充阅读。

## 4. 从一篇笔记开始整理关系

1. 写清当前主题，不必一开始就搭出很大的树。
2. 找出它需要的基础知识，连接前节点。
3. 找出下一步能做的事情，连接后节点。
4. 把过长的原理说明或实践过程拆成下节点。
5. 只有确实可以替换的方案才使用上节点，避免把“需要先学”与“可以任选”混在一起。

在“完善知识树”里，可以从左侧文档列表拖入节点，通过位置预显示判断关系，再完成连接。关系由自己的学习理解整理，界面中的排列不替代内容判断。

## 5. 原文与文档配合使用

- **原文**：直接查看 Markdown 符号，适合精确修改链接、代码围栏和表格。
- **文档**：查看排版后的内容，也可以编辑，适合阅读与整理思路。
- **目录**：根据正文标题跳转，帮助定位长文档中的具体部分。
- **知识树**：从当前文档向外查看相关节点，了解当前知识在学习路线中的位置。

排版帮助阅读，标题帮助定位，知识关系帮助决定下一步。三者配合使用，能够减少“记过但找不到”的情况。

## 6. 图片与分享

- 默认使用相对路径存图；复制粘贴或拖入图片时，图片复制到项目的 `md_photo` 中。
- 图片目录对应文档在 `md_data` 中的目录，只为实际使用图片的目录创建存放位置。
- 正文中的图片地址从当前 Markdown 文件所在目录计算。
- 导出时可以选择携带图片，让导出的文档与图片一起分享，并使用导出后的相对地址。
- 图床地址和绝对路径也可以使用，但分享给别人前要确认对方能够访问。

知识关系保存在项目数据中；单独导出一篇 Markdown 时，正文链接与知识树关系是两个不同的内容，应按分享目的选择文件。

## 7. 每次学习后补上一段复盘

- 我原来以为是什么？
- 实际验证后发现了什么？
- 哪个例子让我理解了这个概念？
- 下次遇到相同问题，我会先检查哪里？

一棵有用的个人知识树会随着学习逐步调整。允许节点位置和关系改变，让它表达自己目前的理解。
