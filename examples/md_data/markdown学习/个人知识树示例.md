# 个人知识树示例

这是一个虚构学习者从 Java 学到前端的文字示例，目标是做出一个“个人学习任务”小应用：能够新增任务、查看列表、标记完成，并在刷新页面后保留数据。它展示知识怎样随着实践逐步连接，不是固定课表，也不要求所有人使用相同技术。

前节点：[tmd作用及其意义](tmd作用及其意义.md)。先理解知识树怎样组织笔记，再看一次完整学习过程。

## 1. 先确定一个能看到结果的目标

我最初只知道想学编程，打开教程以后却不知道该记哪些内容。于是我把目标缩小成一个任务应用：先在控制台里管理任务，再把数据保存下来，最后通过网页使用它。

这样，每学习一个知识点，我都能问：“它帮我完成了哪一步？”笔记里不再只放术语，而是记录目标、尝试、问题和结果。遇到暂时用不到的内容，先留下待查项，完成当前任务后再回来。

- 最小结果：新增一个任务，随后能看到它。
- 下一步：重启程序后，任务仍然存在。
- 最后一步：在网页里完成同样操作。

## 2. Java 基础：先让程序按我的意思运行

我从安装 JDK、编写和运行一个简单程序开始，逐渐学习变量、类型、条件、循环和方法。开始时经常把“输入的文字”与“程序需要的数字”混在一起，因此我先做了一个很小的控制台菜单：输入选项，程序执行对应操作。

练习里最有用的部分不是把代码抄完，而是改动输入：空输入会怎样，输错数字会怎样，循环什么时候结束。程序出现问题时，我把实际结果和预期结果分别写进笔记，再检查条件和变量值。

当我能独立解释一次执行过程，并能修正一个条件判断错误时，才继续进入对象和数据组织。

- 主节点笔记：Java 基础。
- 下节点笔记：控制台菜单练习、输入边界与调试记录。
- 完成依据：不照抄教程也能写出新增、查看、退出三个操作。

Java 的基础主题可以对照 [官方学习入口](https://dev.java/learn/) 逐项补充。

## 3. 对象与集合：让一条任务有自己的结构

起初我把任务标题和状态放进多个变量，很快就分不清哪个状态属于哪个标题。我把一条任务整理成一个对象，让它有编号、标题和是否完成三个属性，再用集合保存多条任务。

我学习类、构造方法和集合时，把“为什么要用”也写下来：对象把相关数据放在一起，集合帮助管理数量变化的数据。随后我把输入输出与任务操作分开，让新增、查询和标记完成的逻辑可以单独检查。

这一步没有急着建立复杂继承结构。我先保证命名清楚、职责明确，再记录自己遇到的异常和无效输入。以后学习接口或泛型时，就能回到这个项目观察它们的作用。

- 主节点笔记：Java 对象与集合。
- 下节点笔记：任务对象设计、重复编号与空标题处理。
- 完成依据：多条任务可以新增、查询和修改，修改其中一条不会误改其他任务。

## 4. 数据库：把运行时的数据保存下来

控制台程序可以使用以后，我发现关闭它就会丢失任务。这个问题让我理解了为什么需要持久化。我先学习表、行、主键，以及新增、查询、修改和删除操作，再给任务建立一张表。

我先在数据库中手动完成一次操作，确认自己理解数据怎样变化，然后通过 Java 的数据库访问方式读写同一张表。查询使用参数绑定，把输入作为数据传入，而不是拼接进 SQL 文本。

练习中，我故意重启程序、查询不存在的编号、修改同一条记录，并比较操作前后的结果。涉及多次写入必须一起成功时，我再学习事务，把失败如何处理也记下来。

- 主节点笔记：SQL 与 Java 数据访问。
- 下节点笔记：任务表设计、参数化查询、重启后数据保留检查。
- 完成依据：程序关闭后再启动，仍能读取之前保存的任务。

## 5. HTTP 与后端接口：把操作提供给其他程序

接下来，我希望网页也能使用任务数据，于是先学习请求方法、地址、状态码和 JSON，再尝试用 Spring Boot 提供 HTTP 接口。这里的关键变化是：后端不再等控制台输入，而是处理客户端发来的请求。

我把任务操作整理成几个明确的入口，例如查询列表、新增任务和修改完成状态。请求进来以后，先校验内容，再交给任务逻辑处理，最后访问数据库并返回结果。我用接口工具分别检查成功、空标题和不存在编号等情况，避免只验证成功的一次请求。

这时的笔记分成两层：主节点说明一次请求的处理过程，下节点分别记录接口约定和异常排查。数据库笔记继续作为前置知识，不再复制一遍。

- 主节点笔记：HTTP 与任务接口。
- 下节点笔记：接口请求示例、参数校验、错误响应约定。
- 完成依据：离开控制台也能通过 HTTP 完成新增和查询，并知道失败时返回什么。

实现思路可以参照 [Spring 官方 REST 服务入门](https://spring.io/guides/gs/rest-service/)，再根据自己的任务需求调整。

## 6. HTML 与 CSS：先做一个能看懂的静态页面

后端能工作以后，我没有立即引入前端框架，而是先做静态页面。HTML 描述页面内容：标题、输入框、按钮和任务列表；CSS 处理布局、间距和视觉层次。我给输入框加上明确标签，让按钮文字说明实际操作。

开始时页面在大窗口里看起来正常，缩小后按钮却挤在一起。我通过调整布局和宽度，再次理解了“页面需要适应不同空间”。这一阶段只用示例数据，先把页面结构和小屏显示做好。

- 主节点笔记：HTML 与 CSS 基础。
- 下节点笔记：任务页面结构、小屏布局、表单标签与键盘操作检查。
- 完成依据：静态页面在宽窄窗口下都可以清楚阅读，表单可以通过键盘操作。

学习材料可以从 [MDN Web 开发学习区](https://developer.mozilla.org/zh-CN/docs/Learn_web_development) 的结构、样式与练习部分开始。

## 7. JavaScript：让页面回应操作

页面有了以后，我希望点击按钮能真正改变内容，因此学习 JavaScript 的变量、函数、数组、对象、事件和 DOM。Java 与 JavaScript 是不同语言，我把它们各自的写法分开记录，只把相似概念作为对照。

我先用页面中的临时数组保存任务：提交表单后加入一项，点击完成后修改状态，再把结果显示出来。做完这一版，刷新会丢失任务是预期行为，因为它还没有连接后端。

这一步让我看清“数据发生变化”和“页面更新”之间的关系。每个事件要读取什么、校验什么、修改什么，都可以写成一段明确的过程。

- 主节点笔记：JavaScript 与页面交互。
- 下节点笔记：表单事件、数组中的任务更新、页面重复渲染排查。
- 完成依据：不依赖后端，也能在当前页面完成新增和标记完成。

遇到语法问题时查看 [MDN JavaScript 指南](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide)。

## 8. 前后端联调：让网页操作同一份数据

我用 `fetch` 向后端请求任务列表，把返回的数据放到页面上。新增任务时，页面发送内容，后端校验并保存，成功后再更新列表。网络操作有等待过程，因此我补上加载状态、空列表提示和失败提示。

这里第一次出现“代码没有抛出异常，但请求其实失败了”。我学习检查响应状态，例如 `response.ok`，再决定怎样读取结果和提示错误；不能把请求完成直接当成业务成功。

开发时页面与接口可能使用不同端口，我继续学习同源与 CORS，把问题记录在联调下节点中。接口地址、请求方法、请求内容、响应状态和后端日志按顺序检查，通常比盲目改页面更容易定位。

- 主节点笔记：前后端联调。
- 下节点笔记：异步请求与错误处理、CORS 配置、重复提交排查。
- 完成依据：网页新增任务后刷新仍能看到它；接口失败时页面给出明确提示。

具体请求处理参照 [MDN：使用 Fetch](https://developer.mozilla.org/zh-CN/docs/Web/API/Fetch_API/Using_Fetch)。

## 9. 组件化前端：让页面更容易修改

当表单、列表和状态提示都写在同一段代码中，修改一个功能会影响其他部分。我选择 Vue 作为这次练习的组件化方案，把页面分成任务表单、任务列表和任务项，并明确各自接收什么数据、发出什么事件。

我重新理解响应式数据：状态变化以后，界面根据状态更新。随后把请求操作集中整理，减少重复的地址和错误处理。这一步是在已有交互基础上重新组织代码，而不是用框架替代对 HTML、CSS 和 JavaScript 的理解。

如果以后学习其他前端方案，可以把满足同一目标的方案整理为同级可替换节点，保留共同的前置知识和后续实践。没有实际学习过的方案先做待学记录，不写成已经掌握的结论。

- 主节点笔记：Vue 组件化实践。
- 下节点笔记：任务表单组件、组件通信、请求逻辑整理。
- 完成依据：修改任务项样式或新增筛选功能时，可以清楚找到负责的组件。

组件和响应式概念可参照 [Vue 官方介绍](https://cn.vuejs.org/guide/introduction)。

## 10. 完整验收与学习复盘

最后，我按一条完整流程使用应用：打开页面，读取任务，新增任务，标记完成，刷新，再查看数据库中的结果。同时检查空标题、不存在的编号、重复点击和接口不可用等情况。

学习完成并不等于能稳定交付。我继续记录怎样构建前端、配置接口地址、启动后端、检查日志和备份数据。每遇到一个实际问题，就把排查过程放到对应主题的下节点里，让主路线保持清楚。

| 阶段 | 我能展示的结果 |
| --- | --- |
| Java 基础 | 控制台任务管理能够运行 |
| 对象与集合 | 多条任务可以独立维护 |
| 数据库 | 重启后数据仍然存在 |
| 后端接口 | HTTP 请求能够完成任务操作 |
| HTML、CSS、JavaScript | 页面结构清楚并能够交互 |
| 前后端联调 | 网页操作真正保存到数据库 |
| 组件化实践 | 页面功能可以按组件继续修改 |

## 11. 把这段过程整理成知识树

主路线按照实际学习的依赖展开：Java 基础 → 对象与集合 → 数据库 → HTTP 与后端接口 → HTML 与 CSS → JavaScript → 前后端联调 → 组件化实践。

每个主节点下面放原理详解、练习、问题排查和复盘；同级可替换方案放在上节点。前端与后端有些内容可以并行学习，后续可以增加分支，让关系反映自己的实际过程。

这篇用文字把完整过程放在一个节点里，便于第一次阅读。上面提到的阶段笔记是后续拆分建议，目前没有额外生成这些文件或节点。开始自己的知识树时，可以先拆出已经学过、已经写清楚的部分。

> 一条有用的学习路线，应当能回答“我为什么学它、我做过什么、我接下来能做什么”。
