# Tmd 文档写入规则记录

更新时间：2026-10-19。N01–N58 及 P01–P13 已确认；最新 N58 确定嵌套列表标记的显示与编号编辑，实际实现与验证记录见 IMPLEMENTATION.md。

## 状态含义

- 已确认：用户明确说明；实现若不符合，以最新确认规则为准。
- 既有确认：此前用户明确选择，继续有效；新一轮回答可以覆盖。
- 待确认：提供备选或发现冲突，不能视为用户已经同意。
- 实现现状：仅用于描述当前程序，不自动成为目标规范。

## 本轮已确认的原则

| 编号 | 原则 | 来源 |
| --- | --- | --- |
| G01 | 文档视图实际编辑 MD，预览用于改善书写观感，原文是内容依据。 | 2026-10-15 用户请求 |
| G02 | 仅紧贴、实际属于语法的一部分的空格与换行可以作为语法加载。 | 同上 |
| G03 | 其余空格与换行允许输入、保留并在文档中显示为空格/换行。 | 同上 |
| G04 | 各语法先说明格式、原文和加载效果，再收集 Enter、Backspace、特殊输入及鼠标操作结果。 | 同上 |
| G05 | 收集并归纳描述后，按确认的规则整体整理、重构写入逻辑。 | 同上 |

G02 的“紧贴且属于语法”必须逐类细化。例如标题前缀后的一个空格、代码围栏行的换行、表格分隔行、段落分隔和硬换行尾部空格，不能仅凭一条通用正则推断。普通正文行首四空格已由 N43 明确为普通缩进；外部导入的标准 Markdown 缩进代码另在导入阶段转换。

| P13 | 文档/原文切换以视口三分之一处对应的源行对齐；两视图均有约半页滚动余量。 |

## 重构方向（技术方案草案）

1. 核心解析在原始源码位置上区分语法标记、结构分隔和普通空白；普通空白保留精确数量与位置。
2. `core/markdown` 中用共同的编辑上下文和原文交易处理按键。结果包含精确修改范围、源码、光标、选区与撤销边界。
3. UI 负责呈现、命中与输入事件，使用核心规则；避免 UI 另写一套与核心不同的语法正则。
4. 每个可见空行、空格和标记边界必须能映射回原文。不要依赖“Qt 导入后丢了什么再猜回来”作为主要方案。
5. 加载、逐字输入、输入法提交、切换视图使用相同本地文档语义；自动渲染不能擅自规范化保存源码。外部导入或普通正文粘贴的缩进代码按用户明确授权的 N43/N49 在导入副本或插入片段转换，再使用统一的本地文档语义。
6. 按已确认场景逐类落地，验证“原文→呈现→编辑→原文”、撤销重做、重载和组合嵌套。
7. 普通缩进与外部导入缩进代码按 N43，硬换行尾部空格按 N03，隐藏定义按 N36。其余尚未明确的语法边界按用户回答决定，新语法扩展单独确认。
