# Tmd 项目结构

## 模块与边界

`tree_md_core` 依赖 Qt Core、Gui 和 Network，不依赖 Widgets。它处理原文、文档状态、路径、关系、图片和配置。`tree_md_application` 依赖核心，统一编辑命令与处理优先级，不依赖 Widgets。`tree_md_ui` 负责 Qt 控件、交互、排版及绘图，通过应用层分发共用编辑交易，其余核心查询保留直接调用。

| 目录 | 职责 |
| --- | --- |
| `application/editing` | 两种视图共用的编辑命令、上下文、优先级及处理结果 |
| `core/markdown/analysis` | 不可变原文快照及指定解析模式的惰性查询复用 |
| `core/markdown/editing` | 共用 UTF-16 单段文本替换值对象 |
| `core/markdown` | Markdown 区域分类、共用标准语义、标题与图片语法、原文位置映射、语言列表 |
| `core/library` | 文档集合与状态、路径约束、原子文件操作、文档交易、批量导入、文件监听 |
| `core/knowledge` | 关系角色、双向及同级规则、持久化、范围索引、稳定拓扑 |
| `core/images` | 图片读取、复制和路径改写、插入、上传、携图导出 |
| `core/settings` | 设置数据与范围、十六进制配置编解码、持久化缓存、共享知识树缩放 |
| `core/platform` | Windows 本机凭据保护、系统文件管理器定位 |
| `ui/document` | 文档与原文视图、排版、高亮、语言补全、图片输入事件 |
| `ui/library` | 文件侧栏、快速搜索、目录列表构建和过滤、正文目录 |
| `ui/knowledge` | 几何布局、连线路由、卡片绘制、画布和完善知识树窗口 |
| `ui/settings` | MD 加载样式和图片保存方式设置窗口 |
| `ui/common` | 主题、圆角弹窗和 Tmd 图标 |

`MarkdownManager` 是文档集合和关系状态的唯一持有者。集合扫描与状态更新、文档交易、关系修改分别实现于 `MarkdownManager.cpp`、`MarkdownDocumentOperations.cpp`、`MarkdownManagerRelations.cpp`，避免拆出多个互相复制状态的管理器。

`DocumentLinkResolver` 在 `core/library` 只做链接解析及库内/库外分类：保留网页协议，解码本地路径，以当前文档目录为基准，兼容库根目录及库名前缀索引，并通过 `LibraryPathPolicy` 判定 MD 是否属于当前库。`MainWindow::openDocumentLink` 接收两种视图的 Ctrl+单击信号，库内 MD 复用文档打开流程，其他目标交给 `QDesktopServices` 调用系统默认程序；常规单击保留编辑行为。

`MarkdownReferences` 提供链接、图片及引用定义的真实地址区间，跳过代码、元数据和其他字面区域；`LibraryReferences` 复用链接路径解析，保留标题、片段和查询参数，只替换地址。`LibraryFileIndex` 将 MD 库与当前图片目录中的文件、目录身份和内容摘要记录到 `.tree-md-files.json`，识别明确移动并保留缺失记录。身份匹配或唯一内容匹配无法确定去向时，原引用保留为缺失，不按相似名称猜测。

`MarkdownReferenceMaintenance.cpp` 归属于同一 `MarkdownManager`，统一处理内部重命名/批量移动、外部文件监听和重启后的地址同步。移动文档自身及未移动文档都参与；保存基线、实际磁盘内容和未保存正文分别替换地址，自动维护不保存用户尚未保存的文字。当前文档通过 `referencesRewritten` 信号沿用 Qt 编辑交易，保留撤销记录。文档名在整个库中按 Unicode NFC 和不区分大小写检查，新建、导入、复制和重命名拒绝重名；外部引入的冲突保留文件并由界面要求重命名。

已知的回收站删除会清除对应历史条目的摘要匹配资格，保留身份记录：原文件还原后仍能识别，新建的同内容文件不能冒充被主动删除的目标。图片目录位于 MD 库内部时复用递归库监听，不为其额外持有会妨碍父目录迁移的通知句柄。

`LibraryScanLock` 按库协调多个进程的扫描和文件交易；每次扫描重新读取共享文件记录，避免同一次移动被其他窗口重复套用。磁盘正文、保存基线和未保存正文分别采用其原始路径进行地址改写，其他窗口的自动修复不视为正文冲突。文件记录提交后才发送正文改写通知。Windows 使用可递归的命名互斥体，进程异常退出会释放；其他平台保留不反复增删的文件锁，避免锁文件本身触发无限刷新。

## 共用的处理入口

- `tmd::EditCommandRouter` 将源码选区、文档/原文模式、表格地址和行内段落边界作为显式输入，分发既有 Code/List/Paragraph/Prefix/Table 规则。两种视图保留自己的 Qt 表格命中、隐藏标记、鼠标框选、IME 与可视折行分支，不再分别维护相同的核心优先级链。
- `tmd::TextPatch` 共用公共前后缀单段替换，并避免切开合法 UTF-16 代理对。`tmd::QtTextEditAdapter` 将编辑结果应用到原文 QTextDocument，检查预期原文与 changed 标记，保留一次 undo、选区和文档页交易前后光标；主窗口与原文编辑器共用此实现。
- `tmd::MarkdownSnapshot` 按 Raw/Rendering 模式持有不可变原文。文档视图与 MarkdownSourceMap 在一次重建、表格边界补正和空白恢复中共用快照；增量修改原文时按内容使旧快照失效。它复用已有分析/语义/图片/代码区查询，不把不同的 renderSource 与原文混用，也不替代源码映射本身的重建。惰性查询仍由 GUI 单线程持有。

- `MarkdownSyntax` 使用 Qt Base 6.11.1 同版本的 MIT MD4C，并经 `MarkdownBlockSyntax::prepare` 统一适配 Tmd 的写入约定。普通源码换行逐行显示；Setext 仅作用于紧邻的上一行，`---` / `===` 至少三个字符。渲染准备产生的转义及分隔有独立标记和原始 UTF-16 位置，不写回文档。渲染与核心关闭专用下划线、HTML 渲染和隐式缩进代码；`_内容_` 为斜体，HTML 显示原文。元数据内部可编辑，边界隐藏，不参与图片加载。
- `MarkdownBlockSyntax::separatorLines` 按最新 N55 统一判定元素下方的第一个空物理行，供文档视图、原文映射和表格退出光标共同使用。标题、正文、列表、表格、引用及闭合代码区之后只消费一行，不依赖下一元素类型；代码及元数据内部、占位空格和额外空行保留。末尾的空编辑位置不视为分隔。Qt 表格导入的无源码占位段落单独处理，不计作用户空行，也不能占用真实空行的光标位置。
- `MarkdownParagraphEditing`、`MarkdownListEditing`、`MarkdownCodeEditing` 和 `MarkdownTableEditing` 是共用的源码交易入口，返回修改后的原文及选区；Qt 视图负责分发按键和呈现。文档页从非空正文/标题建立新段时生成一个隐藏源码分隔，空行上继续 Enter 只新增可见空行；原文页保持逐字换行。列表内部继续项目、代码体及表格单元格使用各自规则。列表操作保持父子关系；表格按整表增删行列，缺格同步补齐原文；修改仍由 Ctrl+S/关闭保存流程落盘。
- `MarkdownImport` 只在文件导入和普通粘贴时按标准 Markdown 找出实际缩进代码并转成围栏，不改外部原件；本地手动输入的四空格保持普通缩进，代码内部粘贴保持字面内容。`MarkdownSpelling` 共用链接、图片、实体及隐藏定义的原文展开范围，并保护部分删除后仍有内容的代码/元数据边界。
- `MarkdownAnalysis::scan` 提供原始 UTF-16 偏移下的代码块、行内代码、HTML 与注释范围。目录、图片发现、代码块渲染和原文映射共用这些结果。代码示例和注释中的图片不参与导入和改写。
- `MarkdownCodeBlocks` 提供成对围栏的语言信息、去除 Markdown 容器缩进后的原始代码及行位置，供复制与原文高亮共用。`LanguageCatalog` 统一语言别名与显示名称。`CodeSyntax` 在核心按语言进行有状态分词，参考 [Prism 标准分类](https://prismjs.com/tokens.html) 和 [highlight.js 状态模型](https://highlightjs.readthedocs.io/en/stable/language-guide.html)，区分关键字、类型、函数、字符串、注释、数字、HTML/XML 标签属性等；支持跨行注释、字符串及 HTML 内嵌 JavaScript/CSS，并提供深浅背景配色。未知语言及纯文本不套用其他语言的规则。
- `CodeSyntaxHighlighter` 仅把核心分词结果映射为 Qt 文本格式，文档与原文视图共用；按代码块身份隔离跨行状态，防止相邻代码块串色。`CodeBlockDecoration` 在文档模式预留标题空间，绘制左上语言标签与右上复制按钮，不插入可编辑文本；复制只取核心解析的当前代码正文，保持光标、选区与 Markdown 原文。
- `LibraryPathPolicy` 共用文件及目录的库内路径校验，检查最近存在的父目录，防止目录链接让路径越过知识库。
- `MarkdownManager::copyDocument` 统一另存为及图片迁移交易。`importDirectory` 保留逐文档错误和部分成功，完成整批后统一扫描，避免每导入一篇就重新读取全部文档。
- `ImageInsertJob` 负责本地、剪贴板、远程与图床图片的处理，开始时捕获目标文档和图片保存配置。主窗口负责进度、错误展示和编辑光标，不再包含图片文件复制和上传后的链接管理逻辑。
- 本地图片默认平铺保存到知识库旁的 `md_photo`，按内容去重，插入、导入及文档迁移均写入绝对引用。图片目录配置只决定保存位置，不再复制文档的目录层级。`MarkdownExportJob` 在携图导出时复制资源并改为相对引用。
- `DocumentTreeBuilder` 供左侧文件列表和完善知识树的未显示文档列表共用，统一目录、文档元数据、标题更新及搜索过滤。

## 刷新与缓存

`documentChanged` 表达内容或保存状态变化，`documentTitleChanged` 只表达标题变化，`documentsChanged` 表达集合刷新，`relationsChanged` 表达知识关系变化。关系修改无需重建左侧文件列表。

文档切换保留 `MarkdownNode` 中的未保存内容，`DocumentTreeBuilder::ModifiedRole` 将保存状态传递给列表委托，右侧圆点不改变文件名或文字拖动命中范围。`documentChanged` 原位更新圆点；保存或恢复原文后清除。`MarkdownManager::modifiedDocuments` 与 `saveAllModified` 负责汇总和批量保存，逐文档沿用原有原子写入及外部修改保护；返回成功和失败路径。关闭窗口仅展示一次汇总提示，失败时保持窗口与剩余编辑，`Ctrl+S` 继续使用单文档保存。

`MarkdownNode::missingReferences` 与 `MissingReferencesRole` 传递本地目标检查结果。缺失引用在同一圆点位置优先显示红色（已保存文档也显示），悬停列出目标；无缺失时沿用未保存白点。文件恢复、地址编辑及图片目录监听都会重算状态。网页和网络图片不以临时联网结果判断失效。文件结构记录为本机运行状态，Git 忽略且发布脚本移除，不随公开示例发布。

每个文档按内容缓存目录和标题。知识树使用集合路径及关系的修订号判断是否需要重建；正文与标题变化保留卡片和连线，标题仅更新文字和提示。切换中心仍使用完整关联树计算稳定布局，再显示五层范围。

`MarkdownSourceMap` 在重建或增量编辑后一次性索引行内代码的显示范围，光标查询使用二分搜索；普通插入无需遍历全部格式容器进行删除判断。文件监听的路径集合在一次扫描结束时统一恢复，包括扫描失败时。

Windows 文件监听使用共享删除权限的 `ReadDirectoryChangesW` 递归监听知识库根目录，并单独监听其父目录，通过 `QWinEventNotifier` 接入 Qt 事件循环；不为每个子目录持有会阻止移动的通知句柄。暂停时先取消异步请求再释放资源，多个实例可以同时监听并移动子目录。其他平台继续使用 `QFileSystemWatcher`。Windows 目录迁移由 `MarkdownDirectoryMove` 负责，先尝试原子移动并短暂重试。Windows 即使允许子目录共享删除，也可能拒绝整体改名其祖先目录；遇到这类错误 5 时，在同卷临时目录暂存目录项，移动空的原目录后再放回内容，保留目录身份、权限和文件身份。深层占用按目录层级处理，明确禁止覆盖、跨卷复制和递归删除；失败时回退，无法完整回退则保留暂存文件并报告恢复位置，图片清理也随之停止。真正拒绝共享删除的占用仍报告具体路径。

完善知识树的“删除选中节点”通过 `MarkdownManager::removeNodeRelations` 一次提交该节点全部入向与出向关系，保留文档文件、编辑状态和其他已存储关系；写入失败不改变内存中的知识关系。画布通过队列信号触发交易，避免在鼠标或键盘事件中销毁卡片。移除中心后重新选取剩余节点，空树通过左侧文档恢复中心。

## 行内编辑边界

`InlineMarkupDecoration` 只调整字符间距与绘制原文标记，不向文档插入空格或符号。边界宽度为当前正文字体普通空格的一半；光标进入行内代码、斜体、加粗、组合强调或删除线时展示实际定界符。合并同范围的复合格式，嵌套格式保留各自边界。代码底色包含显示出的两端反引号，选中内容时边界标记也显示选中色。正文使用 Qt 的逐字符（含组合字符）移动；显示出的定界符由核心记录每个字符的原文位置，界面绘制对应光标，左右键每次仅跨过一个可见字符。相邻或嵌套标记按原文顺序共享边界，点击、插入、删除及重新加载保留精确位置。闭合反引号后恢复正文的字体和无背景样式，后续输入不继承代码样式。删除、插入和撤销仍通过 `MarkdownSourceMap` 修改原文，加载时对格式边界使用精确映射，避免选区偏移。

Enter 与 Shift+Enter 使用相同的段落生成规则（表格使用自己的格内/增行规则）；空列表项继续建立同级项目，空引用按 Enter 逐层退出。标题结束后进入普通正文，引用内标题也退出引用。普通引用正文建立下一引用段。紧邻文字输入 `---` / `===` 可复用 N55 自动分隔形成 Setext 标题；额外可见空行阻止合并，加载已有原文不触发此转换。Tmd 的输入策略额外要求标题、列表、编号列表及引用前缀后有普通空格；Tab 不作为触发空格，单独的 `-` 保持原文，不作用于上一行。

`MarkdownViewport` 为文档和原文视图追加约半页的滚动空间，不插入空段落，不修改文档或撤销记录。切换视图时读取当前视口三分之一高度处的字符，通过 `MarkdownSourceMap` 对应到原文，再将目标视图中的对应行滚动到三分之一高度；每次切换都使用当前视口重新计算。

`DocumentFindDialog` 负责 Ctrl+F 非模态查找/替换窗口及 Tab 模式切换，对当前视图的 `QTextDocument` 做字面查找。带独立标记的 `ExtraSelection` 保存范围、颜色与当前项状态；`SearchHighlightOverlay` 按可见 `QTextLine` 绘制圆角底色，复用原布局绘制字体，不修改文档格式或撤销历史，且只清理自身高亮。文档变化通过零延迟单次定时器合并刷新，后台刷新不自动跳转。

替换只作用于当前项，选中替换后的范围，直到下一次搜索或关闭。原文页用单个 Qt 编辑交易；文档页通过 `MarkdownDocumentView::replaceDisplayText` 调用 `MarkdownSourceMap::replacedText`，只替换匹配文字，保留隐藏 Markdown 容器，并复用现有 `sourceEditStarted/sourceEdited/sourceEditFinished` 交易与共享撤销链。此有界替换与全选覆盖区分：仅有一段加粗文字的文档，查找替换整段文字也保留加粗。保存原文范围并通过 `TextPatch` 跟踪重建前后位置，避免渲染重建后选中漂移；主窗口在切换或重新加载文档时重置保留范围。

`MarkdownBlockSyntax` 集中实现前缀约束、渲染准备及原文偏移映射，将前缀末尾第一个触发空格与后续正文空格区分。文档模式按触发空格立即进入预览，前缀仅在光标进入符号范围时显示；标题、任务等空正文起点的 Backspace 去掉触发空格，保留原始符号，再次输入空格重新进入预览。普通列表空项由 N56 改为直接退出正文，并委托 `MarkdownListEditing` 统一处理前缀移除及段落分隔。核心语义解析和 Qt 渲染共用准备规则；导入空列表或空引用时使用临时标记建立独立段落，随后移除。标记和转义不写入原文。`MarkdownSourceMap` 提供导入丢失的正文起点和行尾空白的精确恢复位置；界面在语义解析后补回可编辑字符，保留标题结束标记、硬换行、代码及元数据语义，更新各块原文边界。隐藏的前缀仍复用行内装饰的逐字符光标、点击和删除机制，中文提交输入也保留准确位置。

`MarkdownCodeEditing` 提供原文上的代码块编辑交易，文档与原文共用。Tab 插入空格到下一个四列缩进位置；多行选择整体增加四个空格。Shift+Tab 每行移除至多四个前导空格或一个制表符。Enter 保留当前行的容器前缀和代码缩进。选区越过围栏时不执行代码缩进，头尾围栏保持不变；空代码块也保留可输入的位置。原文编辑通过单次 Qt 编辑交易保留撤销，文档编辑通过原文变更信号进入现有撤销链。

`MarkdownSelectionEditing` 共用原文范围交易：成对语法包裹、闭合标记的嵌套顺序及代码的行/正文/全文选择。`MarkdownSelectionController` 在两种编辑器中保存待确认标记及 Ctrl+A 阶段，使用浮层呈现输入，不在确认前改写 Markdown；Enter 确认，Esc 取消，Backspace 修正。代码全选阶段显式记录，单行和空代码体也能继续升级，选择操作不产生修改或撤销记录。两个视图分别通过 Qt 编辑适配器和现有 sourceEdit 交易应用同一个核心结果，保留共享撤销及精确原文选区。

`MarkdownListEditing` 共用 `MarkdownEdit` 原文编辑结果，处理列表续写、任务状态复位、Tab 嵌套、Shift+Tab 退一级，以及正文起点的 Backspace 退出列表。退出后保留当前行并补充必要的段落分隔；Qt 省略末尾空正文段落时，由文档视图补回可输入段落。`MarkdownAnalysis` 记录合法嵌套列表的标记位置，四空格缩进仅在已有父列表时作为子列表，独立缩进示例仍属于代码。

`MarkdownAnalysis::Line::listDepth` 记录真实父子列表的层数；`MarkdownListSyntax` 共用列表前缀、源码数字和层级样式，供编辑交易及界面使用。`ListMarkerDecoration` 把这些样式应用到 Qt 列表：无序列表为实心圆、空心圆、小圆点，有序列表为数字、小写字母、小圆点，第三层以后维持小圆点。只有小圆点自行绘制，不缩小正文；任务框沿用原生绘制和点击。点击有序标记通过当前原文映射进入现有前缀编辑器；第二层字母只是一种显示，原文仍为用户的数字，加载和层级变动不会重编号或产生未保存修改。

列表正文起点的 Backspace 优先通过 `MarkdownListEditing::backspaceIndent` 退一级缩进，空列表项也保留预览；没有缩进的普通列表（含空项）一次退格移除完整前缀，本行转正文。`MarkdownBlockSyntax::backspaceEmptyPrefix` 对普通空项委托 `MarkdownListEditing::backspace`，任务项仍恢复完整原始符号，再按一次清除。退出行按需补齐段落分隔，避免上一项吸收该行。没有尾部触发空格的任务标记保持完整字面文本。原文映射使用同一套前缀识别，避免独立正则与渲染规则产生分歧。嵌套编号的必要段落分隔只存在于渲染准备文本，并记录原文位置，不改用户编号。

ATX 标题第一个井号之前的 Backspace 由 `MarkdownParagraphEditing` 判定上一元素（N57）：可见空行逐行上移，普通段落合并为含真实井号的正文，列表/引用/标题/代码/表格等结构边界返回已处理但未修改的交易。文档模式复用 `separatorLines` 跳过隐藏分隔；原文模式按物理行操作。`MarkdownDocumentView` 在图片选择及 Qt 默认合并之前通过应用层路由执行该规则，避免误选上一张图片或吞掉前一元素。标题文字开头还原井号的既有交互继续保留。

引用 Enter 生成带触发空格的引用分隔行；这类段落分隔不注入空容器占位符，避免占位符把相邻引用段合并。代码块首个空行移除后，核心按填补行的 `contentStart` 恢复光标，保留引用与列表容器前缀。仅删除独立代码体时，原文映射跳过整篇删除捷径，围栏留待空块退格交易处理。向下键先按代码段的逻辑行和视觉折行移动，只有最后视觉行允许退出。

主窗口将预览变更同步到原文时，在编辑交易开始前恢复旧光标，在结束前记录新光标，并按 Qt 撤销交易记录前后光标。撤销/重做使用对应交易的光标重定位预览，而不沿用已经失效的原文偏移；原文编辑保留较早的预览交易记录，重新打开文档或改写撤销分支时清理失效记录。

`MarkdownTableEditing` 使用共用渲染准备和 MD4C 的实际表格事件识别行、列及精确原文范围。单元格 Enter 在本格插入 `<br>`，保持分隔行和对齐；缺列的虚拟格按需补充管道符。文档视图为 Qt 表格单元格建立原文边界，空格也能正确输入。原文映射将 `<br>` 对应到一个换行字符，退格删除完整标记，避免破坏表格物理行。

表格后的空白正文段由 `MarkdownTableEditing::paragraphAfter` 提供独立原文位置，避免 Qt 折叠空行后把光标映射到表格内部或下一标题。`insertParagraph` 只在该空段首次输入时补足必要的段落分隔；已有多次换行保持原样。首尾管道符可按 GFM 规则省略，不将未闭合的普通管道文本误认成新的表格。

## 文件列表移动

`DocumentFileTree` 处理侧栏内部拖动和目标预显示，发出移动请求；它不直接调整项目模型或磁盘。`MarkdownManager::movePath` 在 `MarkdownPathMoves.cpp` 集中校验目标、自身子目录及同名冲突。单文档复用重命名交易；文件夹整体迁移保留空目录和其他文件，迁移前准备图片引用，完成后统一更新节点路径及双向知识关系。未保存文档由界面提示处理，核心仍检查修改状态，失败时恢复文档和目录。

目录开合状态按知识库持久保存，重建列表时恢复；文件夹改名或移动同步迁移状态键。拖动经过的关闭目录临时展开，放下或取消后恢复。只有按住条目文字才允许拖动，空白处按住左键框选多个 Markdown 文档，靠近边缘时滚动。`MarkdownManager::moveDocuments` 在整批操作前检查同名冲突与未保存内容，统一更新图片引用和知识关系，失败时回滚已经移动的文档。

目录和文档的颜色由共用 `DocumentTreeBuilder` 定义。目录和空白处的右键菜单支持 `FileManager::openPath` 打开目录；文档右键仅提供新建、重命名、删除。文件列表末尾保留 120 像素可滚动空白，空白处的新建操作以知识库根目录为目标。文件夹重命名与移动共用 `MarkdownPathMoves.cpp` 的交易，保留空目录、图片引用和知识关系。

外部解析源码归 `third_party/md4c`，版本及来源记录于该目录的 README；适配逻辑归 core，视觉边界归 ui。

## 配置与平台实现

`MarkdownSettings.cpp` 定义设置范围和描述，`MarkdownSettingsCodec.cpp` 负责验证、版本兼容和十六进制编码，`MarkdownSettingsStore.cpp` 负责文件读写及缓存。便携导出依旧不带本机图床 Token，Windows 凭据保护归 `LocalCredentials`，原有配置格式保持兼容。

## 构建和检查

CMake 显式列出参与编译的源文件。新增源文件需同时加入对应目标；不要用目录通配自动纳入遗留实现。旧空白 `mainwindow.ui` 与未参与编译且无法独立编译的 `MarkdownOutline.cpp` 已清理。

`tmd_markdown_tests` 检查核心解析、图片导入、原文映射、批量导入和另存为；`tmd_refactor_tests` 检查知识树卡片在正文及标题修改后保持存在；`tmd_library_tests` 检查示例初始化。原综合测试程序仍可直接完整运行，CTest 按文档库、图片、编辑器、知识树、文件界面及设置分组执行。配置阶段检查每个综合测试已被登记，避免新增测试遗漏。

```powershell
cmake --build <Debug 构建目录> --parallel 4
ctest --test-dir <Debug 构建目录> --output-on-failure
```

各组默认按顺序运行，使用临时知识库和隔离配置；Qt DLL 与平台插件需在运行环境可用。原生弹窗键盘检查另用 Windows 平台复验。

语义识别已采用共享解析器，但未保留完整文档 AST，也未将所有图片处理改成后台线程；这两项应由后续大文档及大图实测决定。当前高亮规则保持原有行为，语言分类扩展可使用共享 `LanguageCatalog`。真实图床 API 未接入验证。
